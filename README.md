# Flight Price Analysis & Prediction

## Project objective

Build a data-driven solution to analyze flight prices, uncover the factors that drive costs, and help travelers make smarter decisions.

This project covers both required parts:

- **Part 1 — Exploration:** data cleaning, preprocessing, visual analysis, insights and recommendations.
- **Part 2 — Modeling:** feature engineering, regression modeling, evaluation, feature importance and sample prediction.

## Dataset

The supplied dataset contains **87,692 rows and 18 columns**. The target variable is `Price`.

The raw dataset includes airline, source, destination, departure date, stops, distance, travel class, days before departure, season, weekday, aircraft type, booking channel, passenger count, price, duration, departure hour and time of day.

## 1. Data cleaning and preprocessing

Run:

```powershell
python scripts\01_data_cleaning.py
```

The cleaning step:

- standardizes column names and text fields;
- converts known numeric columns safely;
- parses departure dates consistently;
- removes exact duplicate records;
- removes invalid/non-positive target prices;
- checks for remaining missing values;
- writes `data\flight_pricing_cleaned.csv`.

For the supplied dataset, the cleaning run retains the 87,692 usable records and the source data contains no missing cells after loading.

The modeling stage additionally uses a preprocessing pipeline with:

- median imputation for numerical features;
- most-frequent imputation for categorical features;
- one-hot encoding with `handle_unknown="ignore"`.

## Key insights

The exploratory analysis should be interpreted as relationships in this dataset, not as proof of causation.

- **Distance is a major price-related variable.** Longer routes generally show higher prices in the dataset.
- **Travel class has a strong relationship with price.** Premium classes have substantially higher price distributions than Economy.
- **Airline matters.** Average prices differ across airlines, reflecting differences in route mix, class mix and pricing strategies.
- **Booking timing matters.** Prices vary across different numbers of days before departure, making booking window a useful predictive feature.
- **Stops are associated with price differences.** The relationship should not be interpreted as “stops cause price changes” because route, airline, class and international travel can also influence the result.

## Traveler recommendations

1. **Compare airlines** rather than assuming the first available fare is the cheapest.
2. **Check prices earlier** and monitor the fare as departure approaches.
3. **Compare travel classes** based on the value of the additional services, not only the headline price.
4. **Consider alternative routes or stop patterns** when travel time allows.
5. **Use the prediction model as a reference point**, not as a guaranteed fare, because real-world prices also depend on factors that may not be present in the dataset.

## 3. Feature engineering

The modeling script creates additional features from the supplied fields:

- `Route` = source + destination;
- `Duration_Hours` from `Duration_Minutes`;
- `Month` from `Departure_Date`;
- `Is_Weekend` from the departure date;
- `Booking_Urgency` from `Days_Before_Departure`;

`Flight_ID` and the raw `Departure_Date` are excluded from model inputs. The date is instead transformed into useful calendar features.

## 4. Modeling

Run:

```powershell
python scripts\03_feature_engineering_modeling.py
```

The script compares three supervised regression algorithms:

- Linear Regression
- Random Forest Regressor
- Gradient Boosting Regressor

The data is split into **80% training and 20% testing** using `random_state=42`.

### Current reproducible model results

The included trained artifact was produced by the current modeling script. Random Forest is the best model on the held-out test set.

| Model | R² | MAE | RMSE |
|---|---:|---:|---:|
| Linear Regression | 0.805 | ₹20,505 | ₹28,958 |
| **Random Forest** | **0.873** | **₹12,924** | **₹23,352** |
| Gradient Boosting | 0.699 | ₹27,665 | ₹35,987 |

The Random Forest configuration in the included script uses 20 trees, maximum depth 12, 50% row sampling per tree and 50% feature sampling. This is a lightweight configuration chosen so the full project can be rerun on a typical laptop. An earlier run of the project used a larger Random Forest configuration and produced different metrics; the table above describes the model actually packaged in this final ZIP.

### Metric interpretation

- **MAE**: average absolute prediction error in rupees. Lower is better.
- **RMSE**: penalizes large errors more strongly than MAE. Lower is better.
- **R²**: proportion of variance in flight prices explained by the model on the test set. Higher is better.

The packaged Random Forest achieved an R² of approximately **0.8733**, meaning it explains about **87.33% of the variation in prices in this test set**. This is not the same as saying the model is 87.33% “accurate.”

## 5. Key features driving predictions

The Random Forest's feature importances are calculated after preprocessing and then aggregated back to the original feature names. The resulting table is stored at:

```text
results\feature_importance.csv
```

and the top features are shown in:

```text
visuals\07_feature_importance.png
```

Feature importance indicates how useful a feature was to the fitted Random Forest; it does **not** establish that the feature causally changes price or indicate whether its effect is positive or negative.

## Limitations and future improvements

Flight prices can depend on real-time demand, seat availability, promotions, competitor fares, holidays, fuel costs and other factors not necessarily captured by this dataset. Therefore, the model should be treated as a historical-data-based estimate.

Possible improvements include:

- collecting larger and more recent historical datasets;
- adding real-time availability and demand information;
- adding holiday/festival and airport-level features;
- systematic hyperparameter tuning with cross-validation;
- monitoring model performance on future data;
- deploying the predictor as an interactive web application.
